<1> The service uploads the file to S3 and updates the hotel.
<2> If S3 rejects the upload, for example because the bucket does not exist or the credentials are missing, the AWS SDK throws an `SdkException`. The action logs the exception, adds the `hotel.featuredImage.upload.failed` message to the command object errors, and shows the upload form again, instead of an error page. The exception message is not shown to the user, because it contains AWS details such as the bucket name and the request ID.

The service uploads the file with the `S3Client`, then stores the key and URL:

----
include::../snippets/grails-app/services/example/grails/UploadHotelFeaturedImageService.groovy[indent=0]
----

<1> The `S3Client` bean from `resources.groovy` is injected by name.
<2> The bucket name is read from the configuration.
<3> The hotel is loaded first. If it does not exist, nothing is uploaded.
<4> A random UUID in the key gives every upload its own object and URL. Uploading a file with the same name again does not overwrite the current image, and browsers and CDNs do not keep showing a cached copy of the old one.
<5> `putObject` streams the uploaded file to S3, with its content type.
<6> The SDK builds the object's URL for the configured region or endpoint.
<7> A GORM Data Service stores the key and URL.
<8> If the hotel cannot be updated, or the update throws an exception, the new object is deleted from S3 again. The current image is not touched.
<9> After a successful update, the previous object is deleted.
