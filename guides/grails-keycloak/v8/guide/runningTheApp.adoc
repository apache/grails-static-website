After Keycloak is running and the environment variables are set, start the Grails app:

[source,bash]
----
cd complete
./grailsw bootRun
----

On Windows run `gradlew.bat bootRun` from the same directory.

The application listens on http://localhost:8080[http://localhost:8080].

Public pages should be accessible without authentication. Accessing protected pages will redirect to Keycloak for login; after successful authentication Keycloak returns the user to the Grails app.

== Testing roles

=== Anonymous

Open `/`. The home page renders and the header shows *Login*. `/account` and `/admin` redirect to Keycloak.

=== USER

Sign in as the user who has only the `USER` client role.

* The header shows *Account* and *Logout*. It does not show *Admin*.
* `/account` renders the account page.
* `/admin` is denied. The mapping for `AuthorizationDeniedException` handles that response.

=== ADMIN

Sign out, then sign in as the user who has the composite `ADMIN` client role.

* The header shows *Account* and *Admin*.
* `/account` and `/admin` both render.

If *Admin* is missing for that user, evaluate the ID token again. `ADMIN` must be a composite that includes `USER`, and both roles must appear under `resource_access.example-client.roles`.

=== Logout

*Logout* submits a POST to `/logout` from the `<g:form>` in the header. Grails injects the `_csrf` field Spring Security requires, and `useToken="true"` adds the synchronizer token fields next to it. Keycloak ends its session and redirects the browser to `http://localhost:8080`. A missing post-logout redirect URI leaves the browser on a Keycloak error page instead.
